# Hemnity Gym Member — API Integration Documentation

## 1. Live Backend Inspection & OpenAPI `v2.0.0` Summary (`https://gym.hemnity.in/api/v1/`)

Based on live inspection and the `Hemnity Gym Management Software REST API` OpenAPI `3.0.3` (`v2.0.0`) specification (`GET /api/v1/docs/spec`):

| Method | Path | Auth | Status on Live Server & Android Usage |
|---|---|---|---|
| `GET` | `/api/v1/public/landing` | Public | **Active** — Consumed by Android app for live platform CMS settings (`software_name`, `support_email`, `support_phone`, `support_address`, `legal_privacy_summary`, `legal_terms_summary`, `announcement_banner`, `maintenance_mode`). |
| `POST` | `/api/v1/auth/login` | Public | **Active** — Consumed by Android app (`email`/`identifier`, `password`, `platform`) to exchange credentials for a revocable Bearer API token. |
| `GET` | `/api/v1/owner/dashboard` | Gym Owner | **Excluded** — Intentionally never called from the Member app. |
| `GET\|POST` | `/api/v1/owner/members` | Gym Owner | **Excluded** — Intentionally never called from the Member app. |
| `POST` | `/api/v1/owner/attendance/qr-checkin` | Gym Owner | **Owner Scanner Only** — Validates member `HQR-*` tokens generated by the backend. |
| `POST` | `/api/v1/webhooks/payment` | HMAC-SHA256 | Server-to-server payment webhook. |
| `GET` | `/api/v1/docs/spec` | Owner / Super Admin | **Excluded** — Owner/Admin OpenAPI documentation endpoint. |

- Web Member Portal exists at `https://gym.hemnity.in/member/login.php`.
- The dedicated Member REST endpoints (`/auth/me`, `/auth/refresh`, `/auth/logout`, `/auth/forgot-password`, and `/member/*`) currently return `HTTP 404` (`{"error":"API endpoint not found."}`) on the live server until `/backend_php_extension/` is deployed. The Android app handles `404` gracefully with a direct **"Open Member Web Portal"** fallback action and **never** embeds Owner/Admin tokens or fabricates mock membership records.

## 2. Exact Live Hemnity Schema Alignment

The Android Moshi DTOs (`ApiModels.kt` + `@FlexString` via `FlexStringAdapter`) align directly with the live MySQL/PHP response fields while maintaining compatibility with `/backend_php_extension/member_api.php`:
- **Flexible IDs (`@FlexString`)**: `gym_id` (returned as unquoted int `1` or string `"1"`) and record `id` values are decoded cleanly whether JSON sends numbers or strings.
- **Member & Membership Fields**: `member_code` (`"GYM-2026-0001"`), `full_name`, `phone`, `email`, `status` (`"Active"`), `plan_name`, `membership_start_date`, `membership_expiry_date`.
- **QR Digital Pass Credential**: `active_qr_token` (`"HQR-<32 uppercase hex chars>"`) alongside `qr_payload`, `qr_token`, and `qr_expires_at`.
- **Feature Flags**: `enabled_features_json` array (e.g., `["qr_attendance","member_portal","online_payments","id_card_printing"]`).

## 3. Security & Multi-Gym Isolation Contract

- **HTTPS Only**: `cleartextTrafficPermitted="false"` enforced via `network_security_config.xml`. System trust anchors only.
- **Authorization Header**: `Authorization: Bearer <access_token>` attached automatically by `AuthInterceptor` from Android Keystore AES-256-GCM encrypted storage.
- **Gym Tenant Scoping**: `X-Gym-Id: <gym_id>` header AND `gym_id=<gym_id>` query parameter sent on every member-scoped request. The server validates `member_id` belongs to `gym_id`.
- **Role Enforcement**: `RoleGuard` restricts access strictly to `member` / `gym_member`. Accounts with `owner`, `gym_owner`, `super_admin`, or `admin` roles are rejected on login and session verification.
- **No Sensitive Logging**: `Authorization`, `Cookie`, and `Set-Cookie` headers are redacted in debug builds and logging is disabled in release builds.

## 4. Member API Endpoints Consumed by the Android App

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/public/landing` | Live platform support contact, privacy & terms summaries, announcement & maintenance flags |
| `POST` | `/auth/login` | Member authentication (`email`/`identifier`, `password`, `platform`) |
| `POST` | `/auth/forgot-password` | Request password reset instructions |
| `GET` | `/auth/me` | Validate saved session & confirm member role |
| `POST` | `/auth/refresh` | Rotate access & refresh tokens |
| `POST` | `/auth/logout` | Invalidate server session / refresh token |
| `GET` | `/member/dashboard?gym_id=...` | Welcome summary, active plan, KPIs, unread count |
| `GET` | `/member/gyms` | List all authorized gym memberships for switching |
| `GET` | `/member/memberships?gym_id=...` | Plan details, fee, payment status, renewal history |
| `POST` | `/member/memberships/renew` | Initiate renewal (shown only when `renewal_supported=true`) |
| `GET` | `/member/attendance?gym_id=...&month=YYYY-MM` | Today's status, calendar days, holidays, check-in logs |
| `GET` | `/member/id-card?gym_id=...` | Digital pass details & backend-issued `active_qr_token` (`HQR-...`) |
| `GET` | `/member/payments?gym_id=...&page=1` | Paid/pending totals, payment history, gateway availability |
| `POST` | `/member/payments/initiate` | Create server-tracked gateway payment order |
| `GET` | `/member/payments/{id}/verify?gym_id=...` | Server-verified payment status (never trust redirect alone) |
| `GET` | `/member/payments/{id}/receipt?gym_id=...` | Stream receipt PDF |
| `GET` | `/member/profile?gym_id=...` | Member profile, authorized emergency contact, editable fields |
| `PATCH` | `/member/profile?gym_id=...` | Update only backend-permitted profile fields |
| `POST` | `/member/profile/change-password` | Change password |
| `GET` | `/member/notifications?gym_id=...&page=1` | In-app notification feed |
| `POST` | `/member/notifications/{id}/read` | Mark notification as read |
| `POST` | `/member/notifications/read-all?gym_id=...` | Mark all notifications as read |
| `PATCH` | `/member/notifications/preferences` | Update notification category toggles |
| `POST` | `/member/devices/token` | Register FCM push token |
| `DELETE` | `/member/devices/token?token=...` | Revoke push token on logout |
